## 既有資料如何升級

首次啟動時，如果已有 state.json，本版先在同一私有資料目錄建立 `state.before-resource-content-2026-11-05.json`，再升級 pages、services、news 集合。沒有 state.json 的新安裝直接讀取新初始資料，不建立空白正式狀態。

以舊初始資料作比對基準：後台欄位仍與舊初始值相同時，套用新值；已自行修改的文字、段落、附件與自訂項目會保留。補入新頁面與新服務 ID，新增資源 groups 欄位；其他既有單位、文件、權限、檔案索引及歷史紀錄不改。遷移只執行一次，之後的管理儲存與歷史回復不會再被初始值覆蓋。

若伺服器有人直接修改 data/*.json，仍須在取得 Git 更新前人工合併。程式無法知道伺服器尚未保存到私有 state.json 的獨立檔案變更。

自動狀態備份只保存 state.json，方便檢視升級前資料，不能取代完整資料卷、附件與映像備份。

## 發生問題時

- 只需要恢復程式時：使用保留的前一版映像重新建立本站容器；不要清空資料卷。舊版能忽略新增的群組欄位，原有內容頁說明段落仍保留。
- 需要精確恢復更新前內容時：先停止服務，另存目前資料與新附件，再使用完整的更新前資料卷備份及前一版映像回復。備份之後的新增內容需另行核對與合併。
- Git 端需要記錄撤回時：在確認實際更新提交後使用 git revert 建立回復提交，再重新建置部署。不要使用 force push 或 hard reset 覆蓋他人工作；若之後已有其他提交，不要直接回復不相關變更。
