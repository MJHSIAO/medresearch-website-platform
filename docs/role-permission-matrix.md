# 角色與權限矩陣

## 正式版角色決策（2026-10-16）

單位不再區分編輯者與管理員。同一單位可有多位管理員，均可編輯與發布被授權單位的內容。系統管理員擁有全部功能，不需要兼任醫研部總管理員。

| 功能 | 單位管理員 | 醫研部總管理員 | 系統管理員 |
| --- | --- | --- | --- |
| 編輯、發布與下架內容 | 授權單位 | 全部單位 | 全部單位 |
| 管理醫研部首頁及單位排序 | 否 | 是 | 是 |
| 查看／回復歷史版本 | 授權單位 | 全站 | 全站 |
| 新增、調整或停用單位管理員授權 | 否 | 是 | 是 |
| 任命醫研部總管理員或系統管理員 | 否 | 否 | 是 |
| 修改共用版型與系統設定 | 否 | 否 | 是 |
| 查看操作紀錄 | 授權單位 | 全站 | 全站 |

一般院內人員沒有管理角色。院內登入不等於取得管理權限。醫研部總管理員不得變更高階管理者的角色或停權；正式 API 須驗證操作者及被管理者的權限範圍。

## 結構性欄位

單位正式名稱、網址代碼、隸屬關係、啟用狀態、排序與全站導覽由醫研部總管理員或系統管理員維護；共用版型與系統設定僅由系統管理員維護。

## 目前實作狀態

既有 `admin-demo/` 仍是 localStorage 功能預覽，尚未實作上述伺服器端授權。此次只統一三種角色的介面與文件；角色選單不是帳號任命，也不能保護管理頁面或 API。舊 `unit-editor` 本機值回到單位管理員預覽，不會授予任何伺服器權限。

正式啟用前必須完成：

1. 由後端驗證院方身分，明確設定員工識別欄位與首次系統管理員。
2. 每次頁面、查詢與寫入均驗證角色及單位範圍。
3. 後端依授權設定 `owner_unit_id`，不信任前端角色或 localStorage。
4. 以受控的伺服器儲存層保存授權與稽核，處理撤權、離職及最後一位系統管理員保護。
5. 將功能視角預覽替換為真正的登入身分；完成前不可將目前後台當作正式管理系統。

## 2026-10-21 登入後授權更新

已加入登入後院內專區、本人身分確認與系統管理員環境名單。登入成功改至 internal；admin 與舊 admin-demo 管理路徑由後端驗證 Session，非管理員回傳 403。後端不再提供舊角色切換編輯頁。這取代前述「後端固定 internal_user／管理頁尚未保護」的階段限制；內容寫入與單位授權管理仍未開放。
